# 代码地图生成

将一次开发迭代、一个需求或一段架构流程整理为自包含的交互式 HTML：左侧工程树、中间 Mermaid 图、右侧说明卡可相互定位，顶部导览条按叙事顺序串联主题。

本技能是当前技能集的一部分。生成产物基于实际项目上下文，不包含来源项目、个人信息或无关的示例背景。

## 核心约束

- **生成只替换数据，不修改引擎**：以 `assets/code-map-template.html` 为渲染引擎；通过 JSON 数据或 `MAP-DATA` 区间提供内容。
- **事实可复核**：迭代和评审场景记录实际基线、分支、提交与工作区状态；需求蓝图明确标注“目标态，未实施”。
- **一图一主题**：不将无关需求混入同一张图；已有图更新时保持编号与说明卡 ID 稳定。
- **不暴露无关信息**：标题、说明卡、工程树和示例命令仅描述当前项目及当前任务，不写入个人、来源项目或本地绝对路径。

## 工作流

### 1. 识别场景

先读取 [references/scenarios.md](references/scenarios.md)，按场景确定素材范围、页签和导览方式：教学说明、迭代对比、需求蓝图、变更讲解或架构导读。场景不明确时，先请用户确认。

### 2. 收集事实

- **迭代或变更讲解**：使用 `scripts/extract-diff.sh <项目路径> <基线> [当前引用]` 收集变更，阅读涉及文件并核对实际行为。
- **需求蓝图**：阅读需求和现有结构，区分计划新增、调整与复用内容。
- **架构导读**：阅读顶层目录、入口和核心调用链，只绘制理解主题所需的范围。

不切换用户分支；以当前工作区为事实基线。描述时严格区分已存在行为、建议实现和已验证实现。

### 3. 构建地图数据

优先使用 JSON 契约：

```bash
node <技能目录>/scripts/build-map.mjs --data <map-data.json> --out <输出目录>
```

数据格式见 [references/data-spec.md](references/data-spec.md)，完整字段包括 `meta`、图源码、工程树、说明卡和导览站点。输出默认放在目标项目的 `docs/code-map/<主题>/`；已有同名文件不覆盖，确需重建时使用 `--force`。

无构建环境时，可复制模板和本地 Mermaid 文件，并整体替换 `MAP-DATA-START` 至 `MAP-DATA-END` 的数据区。不可修改数据区外的引擎代码。

### 4. 校验

必须先通过静态校验：

```bash
node <技能目录>/scripts/validate-map.js <输出 HTML>
```

有 Chrome 与 Node 22+ 时，还必须进行真实渲染验收：

```bash
node <技能目录>/scripts/render-map.mjs --html <输出 HTML>
```

静态校验必须为 0 错误。只有渲染报告 `success=true` 时，才能说明已生成 SVG 或 PNG 预览；否则如实说明仅完成静态校验或渲染失败原因。

### 5. 交付

交付 HTML 及实际生成的验证产物，并说明：

1. 顶部导览条按主题主线浏览；
2. 工程树、图和说明卡可相互联动；
3. 左侧工程树支持搜索和折叠。

需求蓝图还应明确：地图描述的是目标设计，导览顺序即建议实现顺序。

## 质量要求

1. `MAP_META.slug` 必须唯一，避免浏览器本地状态冲突。
2. 树节点、图节点、说明卡和导览站点必须可互相对应；`kw` 必须命中至少一个图源码文本。
3. 沿用 `newc`、`oldc`、`extc`、`warnc`、`errc` 五种既定图形语义，不自定义颜色体系。
4. 说明卡写清定位、关键规则和注意事项，避免粘贴大段代码或空泛表述。
5. 更新地图只修改唯一数据源，再重新生成所有派生产物。
